# Local semantic embeddings: the evidence, not the decision

**Status: this document decides nothing.** Issue #94 parks a real sentence-embedding
model "until the list-co-occurrence hybrid proves itself". Whether that condition is
met is a judgement about evaluation results, and it is the owner's. What was missing
was the results. This is them.

Every number here is produced by `make eval` and lives in
`docs/audits/eval-battery.json`; every one is pinned by a literal assertion in
`tests/test_synth_eval.py`, because a property test cannot catch a wrong constant.

---

## 1. Two premises in #94 that had moved

**"A small embedding model … for semantic similarity beyond exact-tag overlap"
reads as unstarted work. The apparatus is already built.**
`recommender/embeddings.py` is on `main` and ships a deterministic, dependency-free
hashing vectorizer behind an `Embedder` protocol, with the constraints #94 calls
non-negotiable already held in code: strictly local, no network, no model download,
and only the *book's own sourced text* embedded — never reading history. It is wired
into `recommend_hybrid(use_embeddings=…)` and gated by `STACKS_EMBEDDINGS=1`, off by
default. What is parked is not "build it"; it is **swapping the hashing vectorizer
for a real model, and turning the signal on**.

**#94 describes the input as "sourced theme tags and descriptions". There is no
description.** `ingest.models.Book` carries `title`, `authors`, `series`,
`identifiers`, `theme_tags`, `pubdate`, `languages` and `publisher` — and no
description, synopsis, blurb or comments field anywhere in the ingest model.
`recommender.embeddings.book_text` is therefore, in full:

```python
" ".join([book.title, *(t.label for t in book.theme_tags)])
```

This matters more than a wording slip, and section 4 is why.

## 2. Has B.1 — the list-co-occurrence hybrid — proved itself?

The battery already measured this; nobody had read it out. Over the ten default
seeds at k=5:

| | median MAP@5 |
| --- | --- |
| popularity baseline | 0.0 |
| content only | 0.71 |
| **hybrid (content + list co-occurrence)** | **0.80** |

Per seed, hybrid minus content: `0.09, 0.20, 0.0, 0.0, 0.09, 0.0, 0.09, 0.2833, 0.0,
0.4267`. **The hybrid never loses to content; it wins on six of ten seeds and ties on
four.** The four ties are seeds where content already sits at 0.8, i.e. at this
world's ceiling — a tie there is not a failure to help, it is no room left.

The curated-list signal is also load-bearing rather than decorative: dropping the
lists costs content a median **0.355** MAP@5.

**One honest caveat before this is read as a verdict.** These are synthetic worlds,
and their curated lists are generated by `_synthetic_lists`, which builds a list from
a third of each seed's *on-canon* books — the same books the eval counts as
positives. The list signal is therefore correlated with the answer key by
construction. That does not make the number meaningless, but it does mean it measures
"the hybrid can exploit a good list" rather than "curated lists in the real world are
good". The real-library dogfood runs (`docs/audits/real-library-dogfood-*.md`) are the
place that second question gets answered.

So: the evidence is favourable and it is not clean. **Calling the park condition met
is a decision, and it is not made here.**

## 3. What the embedding signal actually buys, measured for the first time

Nothing had ever evaluated it. `recommender/eval.py::evaluate` calls
`recommend_hybrid` with `use_embeddings` at its default, so **every committed eval
number in this repository describes the recommender with the embedding signal off.**

The battery now runs a second arm with it on, over the same ten seeds:

| | value |
| --- | --- |
| median hybrid MAP@5, embeddings **off** | 0.80 |
| median hybrid MAP@5, embeddings **on** | 0.80 |
| median delta | **0.0** |
| seeds helped | **1** |
| seeds hurt | **0** |
| seeds unchanged | **9** |

The arm **gates nothing**. `passed` is untouched, and the flag stays off everywhere.
A battery that failed when this delta went to zero would be making #94's decision by
refusing to merge.

---

## 4. Why that zero is not a finding about semantics

**"Semantic similarity does not help here" and "there was nothing to embed" produce
the identical number.** Publishing the first when the truth is the second is this
project's own recurring failure — an absence rendered as a value — so the battery
reports, next to the delta, how much text the embedder actually has:

| corpus | median tokens per book | share that are theme-tag tokens |
| --- | --- | --- |
| synthetic worlds (10 seeds) | 14.0 | **67.94%** |
| demo fixture (8 real titles) | 6.5 | **59.62%** |

Two thirds of the embedder's entire input is the theme-tag text that the content
model is **already matching on exactly**. The remainder is the title — and in the
synthetic worlds the titles are formulaic (`Synthetic Canon Discovery 0-3`), which is
why the demo fixture, with real titles, is measured too. It is better and still a
majority.

So the hashing vectorizer is largely a lossy re-encoding of a signal the content
model already has exactly, and a zero delta is the expected result of that, not
evidence about embeddings.

**This bounds the swap #94 describes.** A real sentence-embedding model dropped in
behind the same `Embedder` protocol would receive the same input: a title and some
tag labels. It would be a more expensive way to approximate tag overlap. The
sentence-level semantics such a model exists to capture are in the text this catalog
does not carry.

## 5. What the owner may want to decide

Listed as questions, not recommendations.

1. **Is the B.1 park condition met?** Section 2 is the evidence, including the
   caveat that the synthetic lists are correlated with the answer key.
2. **Should the sequencing change?** On this evidence the binding constraint on #94
   is not whether B.1 proved itself — it is that there is no text to embed. Sourcing
   book descriptions (a new field, a new source, and a licensing and provenance
   question of its own) would be the thing that makes a real model worth its cost.
   That is a product-direction call.
3. **If a model is swapped in anyway,** "strictly no egress" and "ships a model" need
   an explicit reconciliation — vendored weights in the image, or a documented
   one-time fetch — before any code is written. Downloaded weights are a network
   event somewhere in the lifecycle even when inference is local.

## 6. How to reproduce, and how this was falsified

```
make eval        # regenerates docs/audits/eval-battery.json
make eval-check  # fails if the committed report is not what the code produces
```

Negative controls, each with a committed baseline, `git hash-object` asserted to
change under sabotage and to match exactly on restore:

| Sabotage (a literal) | Result |
| --- | --- |
| `battery.py`: the arm's `use_embeddings=True` → `False` | red — `embeddings_seeds_helped` fell 1 → 0 |
| `hybrid.py`: `EMBEDDING_WEIGHT = 0.1` → `0.0` | red — same assertion, same way |

Both confirm the arm is genuinely running the embedding path rather than reporting a
copy of the embeddings-off number.
